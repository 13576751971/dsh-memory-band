Practical features

四个真正会天天用到的功能

不是“又一个记忆库”。它只做一件事：在模型需要之前，把最该记住的那几百字放到它面前。

01

24 小时保护带

今天和昨天的事单独一份预算，不跟三个月前的旧事抢位置。按 durable → 重要度 → 时间排序，按整条裁，不截半句。

02

命中才召回

2-gram + 话题性单字，本地检索更早的记忆。问“在吗”不加东西；问“那本书”才把相关旧事带进来。

03

自动捕获，不重复

用户的话本地落卡，但当前这句不会在同一轮重复注入；问句不落卡，避免“把问题当记忆”的自我污染。

04

模型可显式调用

一个 memory_band 工具：recall / remember / stats。schema 约 131 token，不用时零调用。

STEP 01
新会话保护带作为稳定前缀注入，按会话缓存。
STEP 02
用户开口本地 2-gram 检索，只补更早、真正相关的那几条。
STEP 03
模型回答能回答就直接答；不够再去读文件或调工具。

Install

三种装法，选一个

插件市场 / 添加插件

本包已经是标准 DSH bundle。在 Plugins → 添加插件 里粘贴：

# npm 发布后
dsh-memory-band

# 或 GitHub 仓库
https://github.com/13576751971/dsh-memory-band

# 或本机目录（开发）
C:\Users\asus\Desktop\GitHub\dsh-memory-band

CLI

装完刷新页面；HMR 会重新组合，通常不用重启。

# 把 profile 换成你的
dsh plugin --profile desktop add dsh-memory-band

# 本地开发自测
node --test --test-isolation=none

数据落在 ~/.dsh/dsh-memory-band/：memory-card.json 是可备份、可迁移的纯 JSON。

Honest boundaries

它不保证每次都能省

模型有随机性。测试里也出现过：记忆带里已经有答案，模型仍然先列目录、读文件，最后才回答。那一次实验组用了 3 个 step，和基线接近。

所以默认页脚写得很直白：“如果这里已经能回答，就直接回答，别再读文件或搜索。”这是把默认行为往“先看记忆”推，不是保证。

它省的是“重复上下文 + 工具往返 + 多余 step”，不是“所有情况都省”。记忆卡为空时，它不注入，也不增加成本。

适合

  • 跨会话的偏好、约定、项目代号、最近发生的事
  • “我们之前说过”“昨天那个”这类对话记忆
  • 不想引入向量库 / embedding API 的本地部署

不适合

  • “某个文件第 7 节写了什么”——这该读文件
  • 纯指代问句（“那件事”），2-gram 猜不出来
  • 需要语义相似、跨语言检索的场景
